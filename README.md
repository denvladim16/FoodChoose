# 🥕 Промо Меню

Седмично меню за вечеря, сглобено около **актуалните промоции на Lidl, Kaufland и Billa**, плюс разглеждане на самите брошури.

Как работи (като в приложението от видеото):

1. Избираш магазин → за колко души → **кои дни и хранения** (решетка 7 дни × закуска/обед/вечеря) → бюджет → какво ти се яде → режим → алергии → месо → уреди.
2. Приложението избира рецепти (103 — 19 закуски, 84 за обед, 75 за вечеря), в които има повече продукти на промоция, и ги вкарва в бюджета. При „Нов план“ избягва ястията от предишния план.
3. Получаваш план по дни с рецепти с макроси, бутон **„Смени ястието“** и **списък за пазаруване** с цената на **цели опаковки** и бутон **„Имам го“**, който маха продукта от сумата.
4. В раздел **Брошури** разлистваш брошурите и търсиш в тях („пиле“, „сирене“).
5. В раздел **Промоции** виждаш основните храни с намалена цена по официалните данни на КЗП.
6. Отгоре на плана има сравнение колко би струвал същият план в другите две вериги.

## Защо има GitHub Action, а не само HTML

Браузърът **не позволява** на страница от `github.io` да чете директно `lidl.bg`, `kaufland.bg` и т.н. Това е защитата CORS: сайтовете не разрешават чужди страници да теглят данните им.

Затова работата е разделена на две части:

| Част | Какво прави | Къде работи |
|---|---|---|
| `scripts/update-data.mjs` | Тегли брошурите и цените и ги записва в `data/*.json` | на сървър на GitHub (Actions), всяка сутрин |
| `index.html` + `js/` | Чете `data/*.json` от същия сайт и показва приложението | в браузъра ти |

Ако `data/` е празна (още не е пускан Action), приложението работи с **ориентировъчни цени** и дава линкове към официалните брошури.

## Откъде идват данните

- **Брошури на Lidl и Kaufland**: платформата `endpoints.leaflets.schwarz`, която официалните сайтове ползват за онлайн брошурите си. Дава снимка на всяка страница, PDF и ключови думи по страница. По тези ключови думи работи търсенето в брошурите.
- **Брошура на Billa**: Billa показва брошурата си в собствен онлайн четец (Publitas). Скриптът търси връзката в billa.bg. Ако не я намери, приложението показва бутон към billa.bg.
- **Цени и промо цени**: отворените данни на КЗП, [kolkostruva.bg/opendata](https://kolkostruva.bg/opendata). По закон всяка верига подава там всеки ден редовна и промоционална цена на основните храни (около 100 вида). Цените са в евро. Скриптът взима последния дневен архив и смята **медианата** от всички обекти на веригата. Промо цената се показва, ако я има в поне 30% от обектите.

> Цените са ориентировъчни, за рецептата: те покриват само количеството, което тя ползва, а не цялата опаковка. Меродавна е цената в магазина. Приложението не е свързано с веригите.

## Качване в GitHub: стъпка по стъпка

### 1. Създай repo

1. В GitHub натисни **New repository**.
2. Име, например `promo-menu`. Избери **Public**, защото GitHub Pages е безплатен за публични repo-та.
3. Натисни **Create repository**.

### 2. Качи файловете

Най-лесно: в празното repo натисни **uploading an existing file** и провлачи **цялото съдържание** на папката (`index.html`, `js/`, `scripts/`, `data/`, `.github/`, `README.md`). След това натисни **Commit changes**.

⚠️ Папката `.github` е скрита. Ако не се качи (на Mac/Windows скритите папки понякога не се виждат):
**Add file → Create new file**, напиши име `.github/workflows/update-data.yml` и постави съдържанието на файла.

С git от терминал:

```bash
cd promo-menu
git init -b main
git add .
git commit -m "Промо Меню"
git remote add origin https://github.com/ТВОЕТО-ИМЕ/promo-menu.git
git push -u origin main
```

### 3. Включи GitHub Pages

**Settings → Pages → Build and deployment → Source: GitHub Actions**

### 4. Разреши на Action-а да записва

**Settings → Actions → General → Workflow permissions → Read and write permissions → Save**

Това е нужно, защото Action-ът commit-ва новите `data/*.json` обратно в repo-то.

### 5. Пусни първото обновяване

**Actions → „Обнови данните и публикувай“ → Run workflow**

След 2–5 минути сайтът е на адрес:
`https://ТВОЕТО-ИМЕ.github.io/promo-menu/`

След това Action-ът се пуска сам **всеки ден в 07:17** българско време и в **четвъртък следобед**, когато Billa сменя брошурата.

### Ако нещо не тръгне

- Отвори **Actions → последното пускане → „Изтегли брошури и цени“**. В лога всеки източник пише какво е намерил, например `Lidl: намерени 4 брошури` или `ВНИМАНИЕ: …`.
- Ако един източник падне, останалите се записват, а за падналия остават последните успешни данни. Сайтът пак се публикува.
- Сайтовете на веригите понякога сменят структурата си. Тогава шаблоните в `discoverSchwarzFlyers()` и `collectBilla()` трябва да се обновят.
- GitHub спира графика на Action-ите в repo без активност от 60 дни. Ежедневните commit-и с данни би трябвало да го държат активен. Ако все пак спре, натисни **Enable workflow** в Actions.

## Структура

```
index.html                     приложението (HTML + CSS)
js/app.js                      логиката: онбординг, план, рецепти, списък, брошури
js/recipes.js                  първите 40 рецепти + каталог на продуктите
js/recipes-more.js             още 63 рецепти (закуски, обеди, вечери) + размери на опаковките
scripts/update-data.mjs        теглене на данните (Node 20, без npm пакети)
.github/workflows/update-data.yml   график + публикуване в GitHub Pages
data/brochures.json            ← генерира се автоматично
data/prices.json               ← генерира се автоматично
```

## Как да добавиш рецепта

В `js/recipes-more.js`, вътре в `RECIPES.push(...)`:

```js
{
  id: 'moja-recepta', name: 'Моята рецепта', e: '🥘', time: 30, kcal: 550, p: 35, c: 50, f: 20,
  app: ['hob'],            // hob | oven | airfryer | microwave
  prot: 'chicken',         // chicken | pork | beef | fish | veg
  tags: ['family', 'bg'],  // fast light family comfort fakeaway gut protein bg
  meal: ['l', 'd'],        // b закуска, l обед, d вечеря (ако липсва — обед и вечеря)
  ing: [['chicken_fillet', 300], ['rice', 150], ['salt_pepper', 1]], // количества за 2 порции
  steps: ['Стъпка 1', 'Стъпка 2'],
},
```

Продуктите се описват в `INGREDIENTS`. Размерът на опаковката е в `PACKS` (в `recipes-more.js`); продукт без размер се брои на тегло. Полето `m` е регулярният израз, по който продуктът се търси в цените на КЗП. `kw` са думите, по които се търси в брошурите. `fb` е ориентировъчната цена, ако няма реална.

## Локално пускане

```bash
node scripts/update-data.mjs        # тегли данните (нужни са Node 20+ и unzip)
python3 -m http.server 8000         # после отвори http://localhost:8000
```

Ако отвориш `index.html` директно с двоен клик (`file://`), браузърът не дава да се прочетат `data/*.json`. Тогава приложението ползва ориентировъчни цени.

## Защо рецептите не се теглят автоматично от Готвач.бг

Сайтът изрично забранява автоматичното четене от AI в `robots.txt`, а текстът на рецептите там е авторски. Затова приложението има собствена база рецепти, а за още идеи дава линкове към Готвач.бг с продуктите, които са в промоция. Така сайтът си получава посещенията.
